# Как добавить нарисованного соперника

Персонаж со спрайтами — это три вещи:

| Что | Где | Зачем |
|---|---|---|
| Спрайты | `public/art/opponents/<id>/` | картинки |
| Манифест | `src/game/characters/<id>.json` | где у картинок плечо, шея, голова и какого они размера |
| Боец | `src/core/opponents.ts` (`OpponentDef`, состав в `ROSTERS`) | имя, баланс, место в карьере |

Других мест нет: список бойцов со спрайтами, фоны и портрет в хабе собираются из манифестов (`src/game/characters.ts`).

## 1. Спрайты

Все файлы рисуются **правкой спрайтов Дяди Бори** — холсты, точки крепления, промты для GPT и подложки для проверки
в [sprite-spec.md](sprite-spec.md). Не берите за основу другого бойца: вместе с картинкой переедут его точки (так был кривой Лёва).
Разрешение может быть больше — сцена приводит картинку к шаблону, — но пропорции должны совпадать.

| Файл | Шаблон | Что важно |
|---|---|---|
| `torso_motion.png` | 1572×1001 | торс без головы и рабочей руки, с обрубком шеи сверху |
| `head_{calm,strain,telegraph,tired,lose,win,press}.png` | 600×700 | все 7 лиц в одной позиции: голова не должна прыгать при смене мимики |
| `arms_motion.png` | ровно 1670×941 | сетка 3×3, 9 поз от его победы до его поражения; кадры совмещены по точкам `ARM_POSES` (`src/game/armMotion.ts`) — рисовать поверх листа Йоса или Бори |
| `arm_free.png` | 560×620 | свободная рука; кулак со штырём на том же месте, что у всех (штырь в точке 501, 493) |
| `cuff.png` | 151×151 | только если стык рукава с торсом виден (сейчас — у Бори) |
| `<фон>.png` | 1280×720 | необязательно; иначе общий подвал |

## 2. Манифест

```bash
npm run new:character -- <id>
```

Скрипт (`tools/newCharacter.mjs`) проверяет, что в папке все спрайты, и пишет `src/game/characters/<id>.json` с точками,
подсказанными **по картинкам** (`tools/characterHints.mjs`): низ шеи головы — по рисунку, масштаб головы — чтобы на экране
она была ростом с Борину, шея торса — чтобы голова встала относительно плеча там же, где у Бори; если срез шеи широкий —
включает растворение. Плечи и масштабы рук берутся у Бори: их задают подложки и лист рук. С ошибками проверки манифест
не пишется. В конце печатается заготовка `OpponentDef` для `src/core/opponents.ts`.
То же делает кнопка «Создать … по картинкам» в редакторе `?rig=<id>`. Манифест соседа не копируй.

Все точки — в px шаблона своей картинки (их видно в любом редакторе картинок):

- `torso.shoulder` — точка торса, куда входит рукав рабочей руки; торс стоит ею на плече листа рук.
- `torso.neck` — середина шеи торса, куда встаёт голова.
- `torso.freeShoulder` — откуда растёт свободная рука.
- `head.neck` — низ шеи на картинке головы; `head.fade` — если обрубок шеи шире шеи торса и ложится
  на одежду прямоугольником, низ головы плавно растворяется между этими строками.
- `torso.scale`, `head.scale`, `freeArm.scale` — px сцены на px шаблона; `arms.scale` — размер связки рук.
- `arms.drop`, `arms.sag` — опустить захват целиком / опускать кулак на пути к нашему штырю.
- `bg` — имя фона в папке бойца, `cuff` — накладка на стык, `bust` — голова на карточке в хабе (em).

## 3. Подгонка в редакторе рига

`npm run dev`, открыть `http://localhost:5173/?rig=<id>`:

1. Включи «Эталон: boris» — поверх рисуется полупрозрачный Боря на том же плече.
   Макушка, подбородок и линия плеч нового бойца должны быть примерно там же.
2. Тяни кружки: «Торс» — тело вверх-вниз по плечу руки, «Шея» — голову по торсу, «Св. плечо» — свободную руку.
   Масштабы и точные числа — полями справа.
3. Проверь пин −1, 0, +1, все лица и технику «press» (корпус наклоняется): не должно быть щелей
   между рукой и рукавом, торчащего обрубка шеи, головы под шкалой пина.
4. «Подсказать точки по картинкам» — показывает, что предлагает подсказка рядом с текущими значениями;
   «Применить подсказку» ставит голову (низ шеи, масштаб, растворение) и шею торса. Это стартовая точка, не истина.
5. Под кнопками — замечания проверки набора, они обновляются на каждую правку. Красные (ошибки) не дают сохранить,
   жёлтые (предупреждения) — разобрать глазами; что значит каждое — [sprite-spec.md §3](sprite-spec.md#3-подключение-и-проверка-в-игре).
6. «Сохранить» пишет `src/game/characters/<id>.json`.

## 4. Проверка

1. `http://localhost:5173/?sheet=<id>` — лист поз: все позиции пина, лица, пресс, топролл и карточка в хабе одной страницей.
   Клик по кадру — во весь экран.
2. `npx vitest run` — `tools/characters.test.mjs` гоняет ту же проверку (`tools/characterValidation.mjs`) по всем бойцам:
   ошибки валят тест, предупреждения печатаются.
3. Бой с бойцом в игре.
4. Новый боец второй версии — добавь его id в `ROSTER` в `tests/visual/sheet.spec.mjs` и запиши эталон:
   `npm run test:visual:update`, затем открой `tests/visual/baseline/<id>/` и посмотри кадры глазами.

## 5. Визуальная регрессия

`npm run test:visual` (Playwright, ~4 мин) снимает лист поз каждого бойца второй версии в headless Chromium
и сравнивает 10 кадров (пин −1…1, лица, пресс, топролл) с эталонами в `tests/visual/baseline/<id>/`.
Сдвиг головы на 5 px уже роняет тест (≈0.75% пикселей при допуске 0.2%). Что разошлось — в `test-results/…/*-diff.png`
(красным) и `*-actual.jpg`. Если изменение задумано — `npm run test:visual:update` и закоммить новые эталоны.
