# SPEC: Фаза 5, итерация 1 — варианты техник внутри семейств

> Статус: черновик на согласование (2026-10-13). Родитель: [plan.md](plan.md), Фаза 5.
> Решения пользователя: управление в реальном времени; первая итерация = варианты внутри 3 семейств;
> открытие через статы + тренировку; готово = ядро `src/core` + тесты + боты, без арта.

## Цель

Сильного соперника можно победить **правильно выбранным вариантом**, а не только семейством
крюк/топролл/пресс. Критерий из плана: «более сильного соперника можно победить контр-техникой».

## Главное архитектурное решение

`Technique` (`hook | toproll | press`) остаётся **семейством**. Треугольник (`BEATS`, `COUNTER`,
`matchup`), арт-позы, звук, HUD и все `Record<Technique, …>` не трогаем.

Вариант — отдельное поле `variant`, как `style` в [styles.ts](../src/core/styles.ts):
чистая функция `applyVariant(stats, family, variant)` правит `PlayerStats`. Так не ломаются ~35 мест
с закрытым union (список в разведке: match.ts, upgrades.ts, opponents.ts, botPlayer.ts, MatchHud, арт).

## Варианты (предложение, названия и цифры — под баланс)

По 2 варианта на семейство; базовый («классика») есть всегда и совпадает с сегодняшним поведением.

| Семейство | Базовый | Вариант 2 | Идея |
|---|---|---|---|
| Крюк | Классический | Глубокий крюк | сильнее, когда идёшь назад (меньше `disadvantage`), дороже по выносливости |
| Топролл | Классический | Высокий топролл | дешевле по расходу, но слабее в старте боя |
| Пресс | Классический | Давящий пресс | ниже `pressGate`, но больший `pressPenalty`, если позиция плохая |

Вариантные контры внутри семейства (мягкие, ±10–15% к силе), чтобы выбор варианта соперника что-то
значил: у соперника тоже есть `variant`, и при `matchup === 0` решает пара вариантов.

## Управление в бою

- Клавиши семейств как сейчас: 1/2/3 (и Q/W/E).
- **Повторное нажатие той же клавиши** переключает вариант семейства (без штрафа `switchPenalty`,
  короткое окно `variantSwitchTime`). В HUD у кнопки показывается текущий вариант.
- Вариант доступен, только если открыт (см. ниже).

## Открытие

Через уровни статов из тренировочного района ([upgrades.ts](../src/core/upgrades.ts)):
- Глубокий крюк: `wrist` ≥ N;
- Высокий топролл: `pronation` ≥ N;
- Давящий пресс: `shoulder` ≥ N.

N подбирается тестами баланса. Новых UpgradeId не вводим (минимум изменений в `emptyLevels`/`emptyXp`).

## ИИ соперника

- В `OpponentDef` добавляется необязательное `variants?: Partial<Record<Technique, VariantId>>`
  (по умолчанию — классика, все существующие соперники не меняются).
- `chooseOppTech` берёт семейство как раньше; вариант — из `variants`. Телеграф остаётся на семействе.
- Сильным соперникам (Лига 2–3) даём фирменный вариант, против которого нужен конкретный ответ.

## Сохранение

`SaveData.variant: Record<Technique, VariantId>` (выбранные по умолчанию), `SAVE_VERSION` 3 → 4,
валидатор в `migrateSave` по образцу `isStyleId`. `save.test.ts` сверяет ключи с `freshSave`.

## Шаги реализации

1. `src/core/variants.ts`: типы `VariantId`, таблица `VARIANT_TUNING`, `applyVariant`, `unlockedVariants(levels)`. + `variants.test.ts`.
2. Подключить в `match.ts`: игрок меняет вариант (`input.variant`), соперник использует `variants`; `matchup === 0` → пара вариантов.
3. Сейв: поле, миграция, версия, тесты.
4. `OpponentDef.variants` + фирменные варианты сильных соперников.
5. Бот `reader` ([botPlayer.ts](../src/core/botPlayer.ts)): выбирает вариант-ответ; ввести бота «variant-reader».
6. UI: подпись варианта на кнопках `MatchHud.tsx`, хоткей повтора в `MatchScene.ts`, тренер `MatchCoach.tsx` подсказывает вариант.
7. Баланс: прогон `npx vitest run src/core`, не сломать существующие ассерты `match.test.ts` (reader vs boris ≥ 0.85 и т. д.).

## Проверка («готово»)

- `npm run typecheck` и `npx vitest run` зелёные.
- Новый тест: прокачанный игрок с подходящим вариантом (variant-reader) побеждает сильного
  соперника заметно чаще, чем без смены варианта (порог задаём по таблице винрейтов).
- Существующие винрейты базовых ботов не просели.

## Вне рамок итерации

Многомерная позиция (угол пина, запястье, высота кисти, пронация, дистанция), King's Move и правила лиг,
арт и позы кисти под варианты, звук. Это итерации 2+.
